# 冻结编码器的8维／32维融合配对

本轮只训练D8、D32各一次seed42。使用同一份N0-seed42第5轮最佳检查点的两套编码器，SHA256=ae65d352ff927026bfcada8759b62f1b22c5d8f0166103d2a2d556618e7a3563。两路仍各自读取完整异构图，保留边属性、Flow／Packet不同池化视角，产生64维表示。关闭统计残差，不改GAT，不加入辅助损失或类别加权。

历史小学习率J2的97.12071203419106%只作实际成绩参考，检查其完成状态、配置／权重哈希和指标，不把该模型权重作为本轮起点。N0来源验证复用旧frozen_fusion.metadata，仅用于冻结划分、来源和检查点身份；不继承旧冻结融合的训练流程、8维缓存或选模预算，不要求E0队列或其他seed先重跑。

## 独立模型与公平初始化

| 部件 | D8 | D32 |
|---|---|---|
| 编码器 | 同一N0参数，冻结且eval | 相同 |
| 两路投影 | 各Linear(64,8) | 各Linear(64,32) |
| 门控输入 | 2×8+5=21维表示统计 | 2×32+5=69维表示统计 |
| 逐维门控 | 21→16→8→Sigmoid | 69→16→32→Sigmoid |
| 共享分类头 | 8→32→8，LeakyReLU | 32→32→8，LeakyReLU |
| 新增可训练参数总数 | 2080 | 7144 |

两组投影、门控隐藏层和分类头均重新初始化，绝不加载成熟N0/V2/J2头部。门控末层权重／偏置都归零，使两组初始融合比例各维均为0.5。两组第0轮不要求相同预测，也不要求复现N0；单独执行的N0回放只验证公共编码器来源及数据一致性。

初始化采用固定seed42派生的按部件命名的CPU随机子流，使用默认Linear初始化规则。这不是换训练seed或多seed筛选。每次部件初始化恢复外部CPU RNG，不触碰CUDA RNG；头部尺寸不同不会消耗后续部件的随机序列。同形状的末层32→8权重及偏置在两组初始时必须逐元素相同。两组正式训练均重置训练RNG到42，采样器也固定seed42。

门控保留原表示统计模板：两路向量、各自softmax归一化熵对应的集中度、top2间隔和两路余弦相似度；归一化熵分母随d采用log(d)。32维是中间表示维度，最终仍预测原8类；这些统计不是攻击类别概率或校准置信度。维度扩展同时改变投影／门控／头部容量和门控输入维度，结论应表述为“维度相关融合结构在本协议下的比较”，不能把差值全部归为一个独立维度组件。

## 仅本次生效的训练设置

按用户后续修订，两组各自最多100轮、patience20，第0轮记录但不参与选模。epoch_zero.json和epoch_zero.pt保存初始状态；best.pt只从第1轮起按验证Macro-F1严格改善保存，即使第1轮低于第0轮也可入选。早停从已训练轮次的最佳值计算。所有历史实验仍保留原来的预算及第0轮规则。

Adam重置，lr=0.001、weight_decay=0，训练batch512、评价batch16，损失仅最终8类输出的NLL。这是本轮新头训练的预先固定设置，不是把旧小学习率微调当作新头训练，也不声称已优化到最佳。使用相同训练顺序，D32在共同轮次首个更新前比对D8采样哈希；两组早停轮数可不同。每完整轮107621样本、211次更新，每组最多21100次正式更新。

冻结不仅依靠requires_grad=False：图模型覆盖train()，总是把两套编码器及全部BN切回eval。头部训练时编码器无梯度；持续核对参数／BN缓冲区哈希。优化器只允许新投影、门控、分类头的全部唯一参数进入，禁止编码器泄漏或遗漏新参数。

## 新64维缓存与正式训练前检查

旧缓存保存投影后的8维表示，不能用于本轮。入口仅创建一次train_encoder64.pt、val_encoder64.pt，保存两路池化后的64维表示、标签、样本ID、冻结编码器哈希、N0权重哈希、划分和顺序身份。两组共用相同内存缓存；从磁盘严格回读并比对后才训练，两组完成时也核对缓存内容哈希不变。缓存头schema明确为xgnid.encoder64-cache.v1，旧维度、错顺序或错来源均拒绝。

服务器训练前必须通过：

1. 严格加载N0最佳状态，重现其全部验证预测及96.9962335% Macro-F1；提取缓存时确认64维形状、样本顺序、标签、有限性及冻结状态不变。
2. 检查两组新头容量、初始化RNG不泄漏、初始门控均为0.5和同形状输出层初始化一致。
3. 两组分别执行相同的3个真实训练batch，检查图输入与缓存预测在1e-5容差内一致，新投影／分类头／门控末层有有限非零梯度并更新；允许零初始化门控隐藏层第一步梯度为零，检查后续更新。
4. 编码器和BN状态必须完全不变，编码器梯度为None。探测后恢复完整状态、清空梯度、恢复RNG和eval模式，丢弃探测优化器；6次探测更新单独记账。
5. 正式训练前先把两组完整新结构保存再严格加载，在真实图上核对输出；任一失败阻止正式训练。

正式训练可以使用缓存，因为编码器始终冻结。每组最佳检查点保存完整图模型状态，包含冻结编码器和对应维度的新头及标签映射；完成后从正确结构严格恢复，在全部13446个原始验证图上核对缓存／图输入输出、8维或32维逐样本权重、预测及混淆矩阵，不能只在缓存中自验。只允许train/val图，不评价测试集。

本地缺少torch/PyG，只执行可运行的无torch逻辑、配置、来源损坏拒绝、缓存身份、参数分组、100/20预算和第0轮排除选模测试，以及Python3.9/Bash语法检查。真实前向／反向、编码器BN冻结和权重回放由服务器执行，未执行的检查不标为通过。本地不做完整训练。

## 结果与解释

输出独立放在outputs/fusion_dimension_pair_s42_v1，D8→D32顺序执行，拒绝覆盖目录／日志／PID。summary.json、analysis.json、report.md及per_class.csv报告：两组Macro-F1、全部8类P/R/F1、D32−D8、相对历史J2的差值、修复／退步及逐类计数、最佳和停止轮次、实际更新量、训练耗时、共享缓存耗时。各组validation_predictions.jsonl.gz保存逐样本d维门控权重及互补Packet权重，graph_replay.json保存原图回放证据。

主要比较D32−D8。若D32优于D8但未超过历史J2，只支持当前冻结／新头协议下的相对收益，不能替换当前实际最好成绩。若两组接近或32维没有优势，不据此认定双分支或所有高维融合均无价值。出现有意义收益并审查类别取舍后，再讨论32维等权融合对照；本轮不自动启动它或其他seed。更大参数容量、随维度变化的门控统计和新头训练协议尚未分别消融，不作统计显著性或独立组件归因。

历史J2使用30轮上限、patience12且更新编码器，其成熟头部和额外预热均不同；只作成绩参考，不称为本轮配对控制。缓存训练耗时不能当作真实图端到端推理成本。共享缓存构建、探测与原图回放另列，不宣称两组总算力或实际更新量完全相同。
