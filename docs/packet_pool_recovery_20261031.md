# P0／P1第0轮读出数值修正与缓存恢复

服务器截图显示fbf812e在训练／验证节点缓存提取后，于 `initial_equivalence()` 的 `Non-equivalent epoch0 readout` 断言退出。该调用位于原图初始回放、梯度探测、P0／P1目录创建及正式训练之前；本次没有正式或探测更新可续接。截图中两个拼接内存估算都可容纳新增分配，报错不是内存不足。

旧实现对均匀注意力计算 `sum(h/n)`，原平均池化为 `sum(h)/n`。数学等价不保证float32结果相同。独立float32小例 `[1e6, 1, -1e6]` 的两种结果分别为0.34375和0.333333343；该小例验证了机制，不能当作已经测量到的服务器实际误差。

修正采用等价计算 `mean(h) + sum((beta - 1/n) * (h - mean(h)))`，权重仍按图softmax，评分网络及其参数布局、1,056个参数均不变。均匀初始化时修正项逐元素为零，梯度仍通过beta连接评分网络。P0、成熟权重、学习率、seed、100／20预算、批大小和第0轮选模政策保持原样。原 `atol=rtol=1e-6` 验收标准不放宽。

新 `initialization_comparison.json` 在全部验证缓存上记录修正前／后的log概率误差、Packet读出误差、门控一致性、预测变化数量及部分样本ID；用于判断服务器的实际问题是否符合浮点归约解释。新实现仍须通过P0／P1初始化一致、成熟源逐样本预测一致、原图回放和真实梯度验收；不能凭小例声称服务器已修复。

恢复入口仅接受绑定fbf812e源码摘要、同一配置、上述明确断言失败且没有P0／P1目录、初始化通过收据或任何后续权重的旧目录。旧目录固定为 `outputs/packet_pool_pair_s42_v1`，完整保留failed状态、error.log及全部缓存。原训练／恢复进程仍在运行时拒绝启动，不结束进程。

恢复写入新目录 `outputs/packet_pool_pair_s42_recovery_v1`：

1. 核对两份节点缓存文件SHA、来源、划分、编码器、样本数量及原提取收据。
2. 复制缓存到新目录，再核对文件和张量摘要、ID／标签／指针／形状及有限性；不重跑全量编码器提取。
3. 从原D32-Gate第62轮分别重建两组干净模型，重新执行初始化诊断、全部初始原图回放、各3次废弃梯度更新及检查点验收，再开始原协议训练。探测不续接旧状态，Adam重新创建。
4. 初始和最佳回放仍读取原验证图；源目录在预检后及完成前逐文件核对，禁止被覆盖或修改。

恢复的图加载计数只包含本次预热、探测及四个原图回放阶段；原缓存提取的107,621／13,446次读取只保留为来源证据，不重复计入本次加载。内存估算保留原提取时的测量并明确标注，不冒充恢复复制／加载时的新估算。缓存复制校验耗时与原提取耗时分开记录。
