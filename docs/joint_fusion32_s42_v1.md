# 32维等权／动态融合的小学习率联合微调

本轮只运行seed42的 `J32-Equal → J32-Gate`。此前32维冻结编码器配对中动态门控领先等权0.176751个百分点、通过原筛选的结论保留。历史代码、配置、缓存和检查点不变。

## 具体变化

| 项目 | J32-Equal | J32-Gate |
|---|---|---|
| 起点 | `outputs/fusion_gate_pair_s42_v1/D32-Equal/best.pt` | 同目录 `D32-Gate/best.pt` |
| 源最佳轮次 | 72 | 62 |
| 起点验证Macro-F1 | 97.14395474565951% | 97.32070542814468% |
| 融合 | 每维固定0.5/0.5 | 已训练的69→16→32逐维动态门控 |
| 可训练部分 | 两路编码器、两个64→32投影、32→32→8分类头 | 相同，再加门控 |

完整严格加载各自最佳模型，不重新初始化融合头，不重复门控预热，不继承旧Adam状态。等权组仍保存但不计算／训练1,664个门控参数，保持原检查点布局兼容。

新模型 `src/xgnid/joint_fusion32.py` 保留原状态键和形状，去掉原冻结模型前向中的编码器 `no_grad()`。训练从真实图计算两路表示，再生成门控输入；固定64维缓存不用于本轮训练。源缓存文件只在继承的完整性检查中校验SHA，不用于编码器更新。

每次调用 `train()` 后，将两个编码器及其子模块固定为eval：BN运行均值、方差、计数等缓冲区不变，编码器参数和BN仿射参数仍可获得梯度。编码器内其他依赖train/eval的运算也采用eval行为。这是本轮设计选择，不代表已证明BN是历史退化的原因。

## 固定协议

新建Adam，weight decay=0，编码器学习率1e-6，两个投影和分类头1e-5，动态门控1e-5。按当前参数名显式分组：

- `flow_encoder.*`、`packet_encoder.*` → encoder。
- `fusion.flow_projection.*`、`fusion.packet_projection.*`、`fusion.shared_head.*` → head。
- `fusion.gate.*` → 动态组gate；等权组冻结并排除。

同组共享参数按对象ID去重；跨组冲突、未知参数或遗漏均拒绝运行。每组学习率、唯一参数数写入各模型 `parameter_groups.json`。两组模型不共享可变参数。

普通最终NLL，train/eval batch512/16，seed42、原划分／特征／标签映射，最多30轮、patience12，验证Macro-F1严格改善选模。**第0轮参与选模，分别对应各自成熟起点，二者不要求输出相同。** 每个完整训练轮211次更新、107,621个样本。公共轮次采样顺序和训练随机起点一致，早停轮数允许不同。不加载测试图。

不同于历史8维J0/J2，本轮使用已训练的32维投影／分类头与69维门控输入，并固定编码器eval行为；旧J2不能作为本轮配对对照。不同于冻结D32实验，本轮开放编码器梯度并改用成熟权重和30/12微调预算。

## 服务器验收

启动先做无torch元数据校验：原32维协议和源码绑定、已完成目录、最佳权重SHA、最佳轮次／指标、配置、逐样本预测及原图回放凭据。任意不匹配均停止，不自动寻找其他检查点。

正式训练前必须通过：

1. 两组完整原验证图第0轮，分别复现源最佳检查点的逐样本预测、混淆矩阵和Macro-F1。
2. 各3批真实训练图前后向／Adam更新探测：两路编码器、两个投影、分类头及动态组门控获得有限梯度并实际更新；等权门控无梯度、无更新。按连续三步窗口检查，允许单步零梯度。
3. 探测期间编码器eval，编码器／BN缓冲区摘要始终不变。结束恢复全部模型参数、缓冲区、梯度和Python／CPU／CUDA随机状态，正式训练重建Adam。6次探测更新废弃、单独记账。
4. 按新结构完整保存、严格重建加载，用真实图短回放；两组训练对象没有共享参数。

所有验收通过才进入两次正式训练。训练每轮检查编码器模式和缓冲区。每组最佳检查点独立重建并严格加载，使用完整13,446个验证原图回放，指标和混淆矩阵一致才完成。第0轮入选时也做相同回放。

## 汇总与判断

主要计算各自新增收益及最终差距：

- ΔE = J32-Equal最佳 − 原D32-Equal最佳。
- ΔG = J32-Gate最佳 − 原D32-Gate最佳。
- 联合后门控差距 − 原有差距 = ΔG − ΔE。

预先固定本轮预算规则：J32-Gate高于 `max(原D32-Gate, 本轮J32-Equal)` 至少0.10个百分点，再考虑后续投入，并审查八类取舍。等权组未超过原D32-Gate时，目标为97.42070542814468%。第0轮可选，因此最终不低于起点不是新增收益证据；同时报告训练后最佳、末轮与相对起点的差值。原有0.176751个百分点不能全部算作本轮联合微调贡献。

完成后交付根目录 `status.json`、`report.md`、`analysis.json`。产物包括：

- 两组 `epoch_zero.json`、`epochs.jsonl`、`best.pt`、`last.pt`、`metrics.json`、`graph_replay.json`。
- 最佳／末轮逐类P/R/F1、混淆矩阵、最佳与停止轮次、更新量、训练耗时；源模型与新模型完整逐类结果汇总于 `per_class.csv`。
- 每组 `validation_predictions.jsonl.gz`，保留每例32维门控权重。
- 每组 `changes_from_own_start.jsonl.gz`，明确列出修复／退步及双方都错但类别改变的样本ID、真类、原预测、新预测。
- 根目录 `gate_vs_equal_changes.jsonl.gz`、`prediction_transitions.csv`，比较最终两组并列出类别去向。
- `initial_checks.json`、`probes.json`、配置／源码／源文件SHA绑定；探测和最终回放时间单独记录。训练时间包含训练、逐轮验证和写检查点，不包含最后独立回放。

重点核对WebBased的FN／FP、Spoofing变化及BruteForce小样本影响。结果只用于该划分seed42的筛选，不声称显著性，不自动追加seed、改结构或评价测试集。

本地无torch/PyG，仅执行无torch合同测试、Python3.9语法、Bash语法和Git归档检查；真实前后向／参数更新、BN缓冲区验证与原图回放由服务器阻断式验收执行，未执行的张量检查不标记通过。
