# XG-NID 后续实验计划（2026-10-17）

本计划依据截至 2026-10-17 的服务器回传结果制定，并按科研重点、创新证据与资源预算反馈修订为 v2。工作方式：本地审查、修改和轻量验证，经 GitHub 交付；服务器拉取后执行真实数据实验。本地不运行全量训练。

## 1. 目标与实验协议

核心问题：边属性是否有效；双分支 logits 门控相对同结构等权融合是否有稳定收益。不能预设改进模型一定更好。

采用两条同步推进的路线：路线 A 在本地开展原论文协议核查与新颖性检索，支撑论文可信度；路线 B 在服务器继续当前冻结分组的 E1→E2→E3，作为模型改进主线。原论文身份暂不可恢复时，不阻塞已冻结且通过检查的分组实验。两套协议分别报告，不能直接跨协议计算模型提升。

这里的“同步”指服务器训练期间推进本地核查、评估工具和文献工作，不表示新增并发 GPU 作业或启动多个未经预算的完整实验。

需要区分三个概念：

- **原论文复现核查**：尽量恢复论文对应的数据、模型、训练和评估过程，逐项列出实际差异。
- **原划分上的受控对比**：各模型共用冻结样本、选模规则和训练配置；若增加验证集等规则，必须标为重实现或受控变体。
- **当前分组协议对比**：已有独立样本清单和输入哈希分组，不能称为原论文严格复现，也不能称为已证明原始流独立。

“原论文表 4 数量一致”不等于“逐样本复现成功”。若原始样本身份、顺序或完整训练设置不可恢复，应明确写出缺失证据，不靠修改测试集或反复试验去追论文分数。

## 6. 阶段 D：继续冻结分组实验链，补足公平性与机制证据

各协议使用独立输出目录和 protocol ID；相同 E 编号仅表示模型角色，不代表数据相同。

| 编号 | 模型角色 | 核心比较与解释范围 |
|---|---|---|
| E0 | 原始参考 Edge 架构 | 基础对照 |
| E1 | 与 E0 同 GAT、仅关闭边属性输入 | E0↔E1：边属性贡献；所有边仍保留 |
| E2 | 双分支 Edge、固定等权 logits 融合 | 与 E0 作整体方案比较；参数量和编码结构不同，不能全部归因于单一因素 |
| E3 | 与 E2 相同双分支、自适应 logits 门控 Edge | E2↔E3：门控融合的独立贡献 |
| 可选 E4 | 与 E3 同结构的 No Edge | 资源允许时研究边属性与门控的交互；正式入口支持后再运行 |

配对比较固定：样本清单、标签、拓扑、节点特征、初始化种子、优化器、学习率、批大小、预算、选模与评估规则。E0/E1、E2/E3 分别核对初始状态和训练顺序。

E1 是自定义同 GAT 受控消融，不是官方 SAGE No Edge 的严格复现。关闭方式固定为不传入边属性项，不能混用删边、零属性或随机属性；属性置零仍可能保留投影偏置效应，不等于关闭。

参数审计同时报告总参数、requires_grad 参数、实际参与前向的模块/路径，以及多批次上 grad is None、梯度存在但为零、非零有限梯度和优化器更新的情况。总参数相同不代表有效参与训练参数相同。E1 保留的边投影、E2 休眠门控和未参与损失的辅助头应单列；不把所有无梯度项都认定为错误，也不以单个批次的零梯度证明参数永远无效。

Contain 敏感性低的核查包括边方向、目标入度、消息传递层和池化路径。单入边下注意力归一化恒为 1 可使边投影无效；用受控小图和真实多入边关系验证解释，不为了增加梯度而直接改变冻结图。关系级建模改动属于后续新版本。

双分支的准确描述为“两个独立参数的完整异构图编码器，分别池化 Flow/Packet 节点”，不称严格隔离的 Flow-only / Packet-only。

第一轮关闭辅助损失、类别权重、hard negative、logit bias 和阈值校准。若另做原仓库 SAGE 无边模型，单独标注“原始不同架构版本对比”，不与 E1 混称。

GPU 首轮顺序：确认/完成分组 E1 → 完成 E2/E3 评估导出的预检查 → 分组 E2 → 分组 E3 → 形成诊断报告和研究决策。原论文核查与文献工作同期推进。分组 E2/E3 使用当前冻结代码完成；独立评估工具不修改训练源码或放宽哈希校验。确需改变模型或训练逻辑时另建版本，并对受影响比较重新验证。

验收：同协议内能生成 E0/E1、E2/E3 对照表；没有同时新增边属性和门控后将提升全归因于门控。

### 6.1 训练前准备可独立运行的机制评估

当前 `train_grouped.py` 的逐样本测试导出只有最终预测与两路权重，门控汇总也主要是整体统计，**不足以支持完整分支互补性分析**。新增独立评估/导出工具，读取冻结配置和检查点，以 eval/no_grad 运行；不改模型训练路径、不更新 BN、不更改权重或 RNG 策略。先在人工小图和真实验证小样本上检查预测与原评估一致，且模型状态前后不变，再启动 E2/E3 全量训练。

优先导出验证集诊断；正式测试仅在模型、全局权重和报告项冻结后执行，并记录额外评估次数。现有结果不足时可重载最佳权重做评估，不必为了增加日志重训模型。

每条记录至少包含 sample_id、真值、最终预测/分数、两分支中间输出、经过共享头的分支诊断分数、gate 权重、实际融合分数；汇总包含：

- 两路诊断的 Accuracy、Macro-F1、逐类 F1、混淆矩阵和预测一致率。
- 两路均对、仅 Flow 池化路对、仅 Packet 池化路对、两路均错四格计数/比例，以及标签可知的“任一路对”诊断上界；该上界不能称作可部署方法。
- 在分支预测不一致子集上，比较等权、全局固定权重和自适应门控的准确率与逐类覆盖率。小子集的 Macro-F1 明确类别支持和缺失类别处理。
- 门控权重整体、逐类、最终预测正确/错误、四格互补子集的分布；检查近 0.5、偏向同一路和随训练/样本变化的程度。
- 把长期接近固定权重视为诊断信号，不能仅凭均值接近 0.5 判定塌缩，也不能仅凭偏向强分支判定实现错误。报告分位数、方差及两端占比。
- 验证集上的 Flow/Packet 原始特征屏蔽仅作敏感性诊断，保留拓扑和未声明屏蔽的其他输入；边属性仍可能携带报文信息，屏蔽也会造成分布偏移，因此不称严格单模态基线。严格单模态结论需要另行定义并从头训练。

**共享分类头的口径**：当前最终预测为 shared_head(w*z_flow+(1-w)*z_packet)，中间 z 虽命名为 logits，但没有独立分支分类损失时，其类别坐标未必具有独立语义。原始 z 的 argmax 只能作附注；主要诊断使用冻结 shared_head(z_flow) 与 shared_head(z_packet)，并标为联合训练模型中的单路推断，不能冒充独立训练的分支模型。中间输出的熵/边际也不自动等于校准的类别置信度。

### 6.2 增加验证集选择的全局固定权重对照

首轮采用无需新增训练的评估对照：分别冻结 E2、E3 最佳检查点的两个编码器、分支投影和共享头，在验证集上按预先固定网格 alpha∈{0,0.05,…,1} 搜索 Macro-F1 最佳的全局比例。并列时优先选择最接近 0.5 的比例，仍并列取较小 alpha；记录完整验证曲线，冻结 alpha 后才评估测试。

对每个检查点使用同一公式 shared_head(alpha*z_flow+(1-alpha)*z_packet)，并列出 alpha=0.5、验证集最佳固定 alpha、原自适应权重（E3）的结果。缓存分支输出可减少重复图读取和前向开销；保留同一共享头，不改成对最终概率另行平均。

这属于**冻结检查点后的融合规则诊断**：E3 的编码器经自适应融合训练，E2 经等权训练，不能仅凭跨检查点结果声称纯推理规则的因果优势。同检查点比较与端到端 E2/E3 比较分别报告。若需完整训练的全局固定权重模型作为主对照，验证选 alpha 后新建 E2-fixed 配置从头训练，并为两侧分配可比训练/选模预算；不默认启动 21 次训练。

现有 E3 含学习门控与置信度平滑混合项；首轮整体比较不拆改。后续若声称某个门控子组件有效，需要新版本单独消融该组件。

### 6.3 预先固定研究决策路径

第一轮根据**验证集**作诊断和资源分配，测试集用于冻结版本的最终报告，不按测试结果搜索算法。以下探索性阈值在追加种子与新版本前记录，不宣称统计显著：Macro-F1 差值 ≥+0.3 个百分点作为值得优先确认的收益信号，≤−0.5 个百分点触发退化诊断，绝对差 <0.2 个百分点视为接近，其余视为灰区。单种子接近不等于无效，仍可进入配对重复验证。

| 首轮观察 | 下一步行动 |
|---|---|
| E3 优于 E2 且优于 E0 | 确认实现和文献差异，优先重复 E0/E2/E3，并完成固定权重与机制分析 |
| E3 优于 E2，但未优于 E0 | 区分门控局部收益与整体方案竞争力；分析双编码器成本、参数预算、分支质量，不只宣传门控增益 |
| E3 与 E2 接近或处于灰区 | 先检查互补四格、预测相关性和全局固定权重；没有实现错误时安排配对重复，不盲目加模块 |
| E3 明显低于 E2 | 检查有效梯度、融合路径、原始中间输出的置信度含义、权重分布和分支质量；有错误则修复并重跑受影响配对 |
| E2 已明显低于 E0 | 优先排查双分支表示与共享头瓶颈，暂不增加门控复杂度；冻结的 E3 首轮用于判断现门控能否补偿该差距 |
| 两路几乎总是同对同错 | 研究表示冗余；优先考虑输入/编码互补性，避免把复杂门控当作默认答案 |
| 存在明显互补但门控未利用 | 检查门控目标、输入尺度、置信度含义，再选择一个有依据的门控修改 |

若需要新算法版本，每轮只选一个主要变化（门控、Packet 编码器、融合位置或关系建模之一），最多筛选 2 个配置，使用独立命名的训练/验证短程实验。该筛选不等同于完整主实验，不能凭小预算直接淘汰尚未收敛模型；最终版本按同一完整规则重新比较。停止无依据的大规模参数搜索。

## 7. 阶段 E：重复实验与开销评估

1. 首轮 seed=42 完成后先按第 6.3 节决策，再建议补充 43、44。不自动同时安排两套协议共 24 次完整训练。
2. 凡要作稳定收益结论的比较，两侧必须有相同预定种子。例如门控与整体方案结论至少重复 E0/E2/E3；若宣称边属性稳定收益，则 E0/E1 也覆盖相同种子。探索性单种子结果另行标注，不只为最佳模型补种子。
3. 在同一冻结划分上报告均值、标准差和同种子配对差值，不以多个种子中最好一次为主结果。训练多种子检验训练随机性，不证明对其他划分、设备或采集场景的泛化。
4. 比较整体 Macro-F1 与逐类 F1，关注 WebBased、Recon、Spoofing、BruteForce，同时保留其余类别。
5. 开销评估统一设备、batch、workers、计时范围、预热与重复次数，分别报告参数量、训练墙钟时间、模型前向时间、含图读取评估时间和 CUDA 峰值分配内存。
6. 服务器早期轮次与后期轮次耗时存在明显差异；资源争用和缓存原因未核实，不能直接把不同时间段的单次耗时差归因于 Edge 或门控。
7. 若采用显著性分析，说明假设和样本单位；三个训练种子仅提供初步稳定性证据，不预设显著提升。

验收：重复结果齐全且无选择性挑种子；没有把前向时间当端到端时延，也没有把 CUDA 分配内存当整张显卡占用。

### 7.1 分阶段资源预算

GPU 小时按“一张 GPU 上作业的墙钟小时”记账，包括其等待图读取的时间；共享服务器上不是独占算力的精确度量。以下是排程预算，E0 的约 6 小时不能直接乘给双编码器。

| 阶段 | 计划上限与执行条件 |
|---|---|
| 首轮分组实验与诊断 | 新增暂按 48 GPU 小时：E1 8、E2 16、E3 16、诊断评估 8；已完成 E0 单列约 6 小时，已运行 E1 的耗时计入 E1 额度 |
| 原论文与文献首轮核查 | 最多 2 个本地工作日形成首版差异表和文献表；不自动占用新的全量 GPU 作业 |
| 新方法候选筛选 | 首轮诊断后才安排；每轮最多 1 个主要变化、2 个配置，总计暂限 8 GPU 小时，单独登记 |
| 多种子确认 | 研究决策后单独编排，暂以 72 GPU 小时为上限；按必要配对分配，估算不足时缩小拟主张范围或重排预算，不省掉对照侧 |
| 原协议完整训练 | 证据具备后先安排一个参考 Edge 基线，依据实际速度单独登记预算，再决定是否需要更多同协议实验 |

每组前 2～3 个完整轮次后，按稳定轮次耗时更新预算，记录预计剩余时间及实际累计。达到排程上限时停止新增任务，先交付现有结果和下一步取舍；不静默增加预算。预算上限不是擅自截断正在进行的公平比较：没有可靠 resume 时不自动杀进程；确需中止则保存并标记不完整，不把截断结果与完整预算结果并列为最终优劣证据。

## 8. 运行体验、恢复与目录管理

- 后续每次交付包含：环境激活、后台启动、PID、实时日志、完成状态和结果读取命令。每次输出独立目录，不覆盖历史结果。
- 现有脚本每轮输出一次；实时 `tail -f` 不等于批次进度。按 Ctrl+C 退出日志跟踪，不应直接推断训练被停止；检查 PID、status 与日志。
- 批次进度（训练/验证百分比、样本数、损失、耗时、ETA）与断点续训作为独立开发事项。原协议新入口优先支持；分组旧入口已被 pilot/E0 哈希冻结，不直接修改后继续套旧报告。
- 目前分组脚本保存了 last/best 和优化器/RNG 信息，但没有 `--resume`。如需新增，先验证模型、优化器、采样器顺序、早停计数、最佳权重、已完成轮次和测试状态的恢复，保证总训练预算不因重启增加，并防止恢复到已完成测试的任务后重复测试。
- 不因代码更新要求结束当前运行任务；新代码、新验证报告和旧任务结果分版本管理。提交 SHA 变化但受校验源码未变时，不等同于模型改变。
- 归档轻量核查文件；保留原图、样本清单、审计清单、必要报告和正式实验。数据、预测明细与大权重留在服务器，不上传 GitHub。
