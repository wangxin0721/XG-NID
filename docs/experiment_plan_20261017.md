# XG-NID 后续实验计划（2026-10-17）

本计划依据截至 2026-10-17 的服务器回传结果制定。工作方式：本地审查、修改和轻量验证，经 GitHub 交付；服务器拉取后执行真实数据实验。本地不运行全量训练。

## 1. 目标与实验协议

核心问题：边属性是否有效；双分支 logits 门控相对同结构等权融合是否有稳定收益。不能预设改进模型一定更好。

优先核对原论文协议并建立对应基线，再开展同协议对照。当前去重分组实验保留，作为控制精确输入重复后的另一组证据。两套协议分别报告，不能直接跨协议计算模型提升。

需要区分三个概念：

- **原论文复现核查**：尽量恢复论文对应的数据、模型、训练和评估过程，逐项列出实际差异。
- **原划分上的受控对比**：各模型共用冻结样本、选模规则和训练配置；若增加验证集等规则，必须标为重实现或受控变体。
- **当前分组协议对比**：已有独立样本清单和输入哈希分组，不能称为原论文严格复现，也不能称为已证明原始流独立。

“原论文表 4 数量一致”不等于“逐样本复现成功”。若原始样本身份、顺序或完整训练设置不可恢复，应明确写出缺失证据，不靠修改测试集或反复试验去追论文分数。

## 4. 阶段 B：核对原论文与官方实现的实际协议（下一项优先开发工作）

建立逐项差异表，分别标明来源：论文、固定提交的官方代码、服务器数据，或尚未确定。

| 核对范围 | 要核对的内容 |
|---|---|
| 数据来源 | 官方预处理版本、现有 CSV/图 SHA256、图与 CSV 行对应关系 |
| 划分身份 | 明确原 train/test 身份；采用显式路径和样本 ID，不直接套递归字典序的历史索引 |
| 样本数量 | 表 4：训练 8 类各 20000，共 160000；测试六类各 4000，WebBased 1090、BruteForce 467，共 25557 |
| 重采样与重叠 | 核查复制补足发生的阶段，分别记录集内重复和跨集输入重叠；不把复制行当独立流 |
| 图构建 | Flow82、Packet1500、三类关系、双向 Link、Contain4/Reverse4/Link1、标量属性适配 |
| 模型 | 原始 Edge 类、两层 GAT、实际关系聚合、预测头、BN eps、自环和池化规则 |
| 训练 | 学习率、优化器、批大小、轮数、有效 weight decay、调度器、随机种子和初始化 |
| 选模与评估 | 是否有独立验证集、使用最终权重还是最佳权重、是否曾利用测试成绩选模型 |

特别注意：

- 当前官方参考类保存了名为 `aggr` 的参数，但构造 `HeteroConv` 时未显式传入它；应根据固定源码和实际 PyG 默认行为核实，不能看到 `aggr="mean"` 就认定有效聚合为 mean。
- 官方 Notebook 示例可见 batch_size=64、lr=0.01、epochs=30；这是**示例代码设置**，尚不能直接认定等于论文最终配置。当前分组实验为 batch_size=16、lr=0.001、最多100轮、验证 Macro-F1 早停，存在明确差异。
- 官方 Edge 使用 GAT，无边版本使用 SAGE；其原始模型对比与同 GAT 的单变量边属性消融是两种实验。
- 旧记录的 144000 / 16000 / 25557 不应自动称作论文原划分；需要核对其生成过程和图身份。
- 服务器输入审计结论只针对该数据版本，不能单凭它认定作者原始实验存在泄漏。

验收：每个核心设置有来源或被明确标为未知；原训练/测试样本清单可定位且可校验；完成独立性限制说明。

若只能恢复数量而不能恢复身份，则继续以“原论文协议重实现”推进，并在报告中标明证据级别。若原划分存在精确输入跨集重复，保留事实供复现核查；它对模型比较结论的限制须与分组实验一起报告。

## 5. 阶段 C：准备独立原协议入口并完成 Edge 基线

本阶段是**待开发任务**，现有 `train_grouped.py` 不直接替代原协议入口。

1. 冻结经过核对的官方模型版本和显式 train/test 清单，建立独立 protocol ID、配置文件与输出目录。
2. 在原协议模式中保留已核实的训练和评估规则。若官方仅提供 train/test 与固定轮数，不擅自添加验证早停后仍称严格复现。
3. 受控对比需要验证集时，仅从原训练部分建立固定分组验证集；同一输入组不跨训练/验证，过采样仅作用于最终训练部分。该方案另设 protocol ID，并明确偏离原表 4 的训练使用方式。原测试成员不因调参而改变，已有 train/test 输入重叠另行记录。
4. 先用少量真实训练数据做前向、反向、一次更新和训练循环检查，再启动完整原协议 Edge 基线；预检查不使用测试集选配置。
5. 实验成功后保存 Accuracy、Macro-F1、Weighted-F1、逐类指标、混淆矩阵、预测、权重和实际用时；与论文结果并列，注明所有差异。

验收：Edge 属性实际进入消息传递；数据与模型来源可追溯；选模规则预先固定；完成状态和真实测试结果齐全。分数接近论文不是唯一验收条件，差异不能靠测试集调参消除。

交付预期：原协议差异表、独立训练配置和入口、服务器检查与启动命令、原协议 Edge 结果。文件名和命令在实现后确定，不把本计划当作可执行命令。

## 6. 阶段 D：按同一协议完成受控实验链

各协议使用独立输出目录和 protocol ID；相同 E 编号仅表示模型角色，不代表数据相同。

| 编号 | 模型角色 | 核心比较与解释范围 |
|---|---|---|
| E0 | 原始参考 Edge 架构 | 基础对照 |
| E1 | 与 E0 同 GAT、仅关闭边属性输入 | E0↔E1：边属性贡献；所有边仍保留 |
| E2 | 双分支 Edge、固定等权 logits 融合 | 与 E0 作整体方案比较；参数量和编码结构不同，不能全部归因于单一因素 |
| E3 | 与 E2 相同双分支、自适应 logits 门控 Edge | E2↔E3：门控融合的独立贡献 |
| 可选 E4 | 与 E3 同结构的 No Edge | 资源允许时研究边属性与门控的交互；正式入口支持后再运行 |

配对比较固定：样本清单、标签、拓扑、节点特征、初始化种子、优化器、学习率、批大小、预算、选模与评估规则。E0/E1、E2/E3 分别核对初始状态和训练顺序。

双分支的准确描述为“两个独立参数的完整异构图编码器，分别池化 Flow/Packet 节点”，不称严格隔离的 Flow-only / Packet-only。

第一轮关闭辅助损失、类别权重、hard negative、logit bias 和阈值校准。若另做原仓库 SAGE 无边模型，单独标注“原始不同架构版本对比”，不与 E1 混称。

顺序：原协议核查 → 对应 Edge 基线 → 对应受控 E1 → E2 → E3。已有分组 E0 和已启动的分组 E1 保留；分组 E2/E3 使用当前冻结代码完成，或在有明确版本变更时另建版本并重新验证，不悄悄放宽已有源码校验。

验收：同协议内能生成 E0/E1、E2/E3 对照表；没有同时新增边属性和门控后将提升全归因于门控。

## 7. 阶段 E：重复实验与开销评估

1. 首轮 seed=42 完成后，建议补充 43、44；E0～E3 均按相同规则运行三个训练种子，不只给表现最好的模型补种子。
2. 在同一冻结划分上报告均值、标准差和同种子配对差值。训练多种子检验训练随机性，不证明对其他划分、设备或采集场景的泛化。
3. 比较整体 Macro-F1 与逐类 F1，关注 WebBased、Recon、Spoofing、BruteForce，同时保留其余类别。
4. 开销评估统一设备、batch、workers、计时范围、预热与重复次数，分别报告参数量、训练墙钟时间、模型前向时间、含图读取评估时间和 CUDA 峰值分配内存。
5. 服务器早期轮次与后期轮次耗时存在明显差异；资源争用和缓存原因未核实，不能直接把不同时间段的单次耗时差归因于 Edge 或门控。
6. 若采用显著性分析，说明假设和样本单位；三个训练种子仅提供初步稳定性证据，不预设显著提升。

验收：重复结果齐全且无选择性挑种子；没有把前向时间当端到端时延，也没有把 CUDA 分配内存当整张显卡占用。

## 8. 运行体验、恢复与目录管理

- 后续每次交付包含：环境激活、后台启动、PID、实时日志、完成状态和结果读取命令。每次输出独立目录，不覆盖历史结果。
- 现有脚本每轮输出一次；实时 `tail -f` 不等于批次进度。按 Ctrl+C 退出日志跟踪，不应直接推断训练被停止；检查 PID、status 与日志。
- 批次进度（训练/验证百分比、样本数、损失、耗时、ETA）与断点续训作为独立开发事项。原协议新入口优先支持；分组旧入口已被 pilot/E0 哈希冻结，不直接修改后继续套旧报告。
- 目前分组脚本保存了 last/best 和优化器/RNG 信息，但没有 `--resume`。如需新增，先验证模型、优化器、采样器顺序、早停计数、最佳权重、已完成轮次和测试状态的恢复，保证总训练预算不因重启增加，并防止恢复到已完成测试的任务后重复测试。
- 不因代码更新要求结束当前运行任务；新代码、新验证报告和旧任务结果分版本管理。提交 SHA 变化但受校验源码未变时，不等同于模型改变。
- 归档轻量核查文件；保留原图、样本清单、审计清单、必要报告和正式实验。数据、预测明细与大权重留在服务器，不上传 GitHub。
