# E3 自适应门控代码审查（2026-10-20）

范围：`src/xgnid/model.py`、`src/xgnid/edge_experiments.py`、`scripts/train_grouped.py` 与既有机制/冒烟证据。只做源码阅读、公式推导与标准库静态核对；未改冻结代码、配置、数据或结果，未执行模型、重新评价或训练，未实现 M1。没有读取服务器当前 E3 检查点，不能将任何结构风险认定为本次低分的实际原因。

## 已核实的计算路径

每路接收完整异构图，两套编码器参数独立，分别池化 Flow / Packet，得到 h_f/h_p∈R64；各自线性投影得到 z_f/z_p∈R8。这里的变量名是 flow_logits/packet_logits，但没有独立的分支分类损失。最终分类使用 H(w_f z_f+w_p z_p)，H 为 Linear8→32、LeakyReLU、Linear32→8。

门控输入为两路 z、两路 softmax(z) 熵补量 c、两路 top1-top2 间隔 m，以及 cosine(z_f,z_p)，共 21 维。门控为 Linear21→16、LeakyReLU、Linear16→2、Softmax，得到 g。最终权重为 w=(0.9g+0.1c)/(0.9+0.1(c_f+c_p))（忽略正常范围不触发的分母 clamp）。冻结训练只优化最终 NLL。

静态路径中门控被 E3 开启，softmax 轴和归一化轴都是最后一维，融合后确实进入 shared_head；没有 detach 截断门控/代理量路径。既有服务器冒烟记录验证了 E3 门控非零梯度。这足以支持“路径可训练”，不足以支持“已经学到可靠的分支选择”。

## 审查发现（按优先级）

### 1. 高优先级：置信度与一致性代理没有已确认的分类语义

位置：`model.py:653`、`model.py:676`、`model.py:683`、`model.py:703`、`model.py:731`；训练目标在 `train_grouped.py:255`。

已确认：z 由独立 Linear64→8 产生，只通过融合后的 H 接受最终 NLL；没有分别对 z_f/z_p 做类别监督。softmax(z) 的低熵、较大 top1-top2 间隔不能直接解释为分支预测更准确，cosine(z_f,z_p) 也不能直接解释为类别预测一致。

影响：门控可能接收到与真实分类可靠性不一致的代理信号；尤其是代理量还被直接混入最终权重。缺少分支监督不证明 z 完全不含类别语义，也不证明模型必然无法学到有用表示；该风险需要验证集证据。

需要验证：分别导出 z 和 H(z) 的输出，检验 c/m 对 H(z) 对错的区分能力；不要用 argmax(z) 直接替代分支分类结果。H(z_f)、H(z_p) 是同一融合模型的推断干预，不等同于独立训练的分支模型。

### 2. 高优先级：代理与门控依赖未经对齐的表示尺度，并参与同一训练反馈

位置：`model.py:434`、`model.py:653`、`model.py:676`、`model.py:699`、`model.py:723`。

已确认：两路线性投影独立；输入门控的 z 未进行统一尺度处理；c/m 直接由 softmax(z) 计算，没有温度校准或独立可靠性目标，且没有 detach。

公式性质：正比例缩放非均匀 z 能改变 softmax(z) 的熵和间隔，而不改变 argmax(z)；更重要的是，实际预测还经过 H，因此这些变化本身不能证明准确率变化。对两路同时施加 z′=a z（a>0），并将 H 第一层权重除以 a，在固定融合权重时能够保持最终分类函数不变，但 c/m 一般改变。对表示共同平移 z′=z+t·1，softmax(z) 不变，余弦相似度却一般改变；固定融合权重时可通过调整 H 第一层偏置补偿该平移。上述是表示代理的坐标依赖性说明，不声称当前动态门控的完整函数在这些变换下也不变。

影响推断：门控可能偏好尺度更尖锐的表示，而非更可靠的分支；最终 NLL 同时经直接融合和门控/代理路径影响编码器，存在相互强化的可能。没有独立监督并不妨碍最终 NLL 训练门控；未 detach 也不是自动成立的程序错误，不能未经消融就直接切断梯度。

需要验证：逐样本记录两路范数、c/m、分支 H(z) 正误及最终权重，判断表示尺度与权重是否强相关、是否确实伴随错误选择。

### 3. 中优先级：固定混合系数的实际含义与防塌缩作用有限

位置：`model.py:723`、`model.py:724`。

已确认：c_f/c_p 各自是熵补量，通常不满足 c_f+c_p=1。设 s=c_f+c_p>0，q=c/s，可重写为：

```text
w = α g + (1−α) q
α = 0.9 / (0.9 + 0.1s)
```

在理想精度 c∈[0,1] 时，置信度分布的有效总占比从 0 到 2/11≈18.18%，不是固定 10%；s=0 时 w=g。两路 c 同为正数且相等时，该项将权重向 0.5 拉回，即使这两个相等值并未提供区分分支的证据。例：g=[0.9,0.1]、c=[1,1]，最终 w≈[0.8273,0.1727]。

该混合不是时间/跨样本平滑正则，也不保证每路存在统一的正权重下限：某路 c≈0、g≈0 时其 w 仍可接近 0。此时该分支的直接融合梯度会缩小，但仍可能有间接门控梯度，不能断言它完全停止学习。

当前 0.9/0.1 是代码中固定的启发式设置，缺少该次独立消融证据。E2 对 E3 的比较同时包含可学习门控及此代理混合，不能把差异全部归因于纯学习门控。任何去除混合或改变系数的验证都应在首轮完成后的独立版本进行，不改当前 E3。

### 4. 中优先级：门控没有保证从等权功能起点开始

位置：`model.py:418`、`model.py:655`、`model.py:711`、`edge_experiments.py:68`。

已确认：门控线性层没有专门的等权输出初始化；E2 直接绕过门控固定 0.5，E3 一开始使用门控和代理混合。配对 state_dict 相同不等于两者初始预测函数相同。

可能影响：E3 早期可能改变两个分支获得的直接梯度份额；若某一路过早占优，可能增加联合优化难度。当前没有最初实际权重与分支梯度的完整记录，不能断言已经发生偏置或塌缩。即使将门控最后一层设成输出等权，后续不相等的 c_f/c_p 仍会改变最终权重；不能只改最后一层就声称实际融合一定从 0.5/0.5 开始。

这不使现有 E2/E3 对照无效，也不要求必须增加 warmup；只是后续解释优化轨迹时需要区分参数配对与功能起点。

### 5. 中优先级：双分支互补性未得到保证，并存在不参与主损失的计算

位置：`model.py:637`、`model.py:645`、`model.py:667`、`model.py:690`，编码器最后一层关系见 `model.py:72`。

已确认：两路都接收完整 Flow/Packet 图，区别包括独立参数和池化节点类型，不能称作隔离的 Flow-only / Packet-only 网络。它们也不一定冗余，池化路径确有差异；但当前没有保证其互补性的训练约束或评估证据。

在正常两层关系路径中，Flow 池化分支最后一层输出到 Packet 的两类卷积不进入最终分类路径；Packet 池化分支最后一层输出到 Flow 的卷积同样不进入该路径。这些输出仍会计算，其 BN buffer 可在训练时更新，但相应末层卷积权重不由主分类损失更新。`webbased_head` 等辅助头也被计算和缓存，而冻结训练未调用 model.loss，相关辅助头不连接主损失。

这是 E2/E3 共用结构的有效容量/成本限制，不能单独用来解释 E3 相对 E2 的差距。总参数 846800 不等于全部参数都参与有效训练；门控网络本身仅 (21×16+16)+(16×2+2)=386 个参数，不能仅凭增加门控就断言整轮耗时翻倍。

### 6. 中优先级：先压到 8 维再加权，限制了融合后的可恢复信息

位置：`model.py:653`、`model.py:659`、`model.py:726`。

已确认：每路 64 维先线性压到 8 维，最终将两路 8 维加权相加；shared_head 无法恢复在该融合映射中丢失的区别。joint NLL 可以促使投影形成有利于分类的公共坐标，但并无显式的两路坐标对齐或独立类别语义保证。

潜在影响：若任务有用的两路差异在投影/求和中被消除，后续分类头无法补回。但 8 类任务使用 8 维表示本身并不是错误，不能静态推断它必然损害准确率。此项同样是 E2/E3 共用设计，需要与门控专属问题分开归因。

### 7. 中优先级：当前日志与导出不足以定位门控失败

位置：`model.py:732`、`train_grouped.py:110`、`train_grouped.py:129`、`train_grouped.py:267`、`train_grouped.py:301`。

已确认：cache 保存最终 w、z、c/m/余弦和部分辅助输出，但不保存混合前 g、门控 softmax 前值或单独 h_f/h_p。evaluate 只汇总最终权重的均值、标准差、极值和超过 0.95 的比例；逐轮 epochs.jsonl 不写这些门控统计。最终预测 CSV 仅含样本身份、标签、最终预测和最终两路权重，验证阶段不导出逐样本分支预测。

影响：总体平均接近 0.5 不能区分“每个样本几乎都 0.5”与“按样本正确/错误地偏向某一路”；权重集中也不等于塌缩有害。现有 epoch 日志无法证明门控在选正确分支，也无法判断问题来自原始学习门控、代理混合、分支质量或缺少互补性。

后续应通过独立服务器评估读取冻结检查点导出这些字段，而非修改正在运行的训练入口。所需字段在既有 `e3_mechanism_audit_20261017.md` 已列出。

### 8. 较低优先级且非门控特有：训练损失与 Macro-F1 的类别计权不同

位置：`train_grouped.py:255`、`train_grouped.py:270`；冻结入口未使用 class_weight。

已确认：NLL 按训练样本平均，验证选模使用每类等权的 Macro-F1。两者并不直接优化同一目标；如果稀有类表现弱，总体 Accuracy 改善不保证 Macro-F1 改善。

这是 E0/E1/E2/E3 的共同协议选择，不是 E3 独有的 bug，更不能单独证明其低分原因。当前保持受控协议，不能因测试表现弱就为 E3 单独启用类别权重或辅助损失。

## 结论与下一步证据

最优先的审查问题是：当前 c/m/a 是否确实能反映分支可靠性，以及最终权重是否利用了互补信息。尚未发现门控未启用、最终输出绕过门控或静态梯度链路被 detach 的接线问题；没有足够运行证据宣布当前发生门控塌缩、置信度失效或训练 bug。

保持当前 E3 冻结训练。结束后先在验证集、同一冻结检查点下对齐比较 H(z_f)、H(z_p)、H(0.5z_f+0.5z_p)、原始动态融合，结合原始 g/最终 w、c/m、范数与逐类正确组合判断实际问题。单路与等权干预并非独立重训模型，不能混作新的端到端训练对照。任何固定 α 选择只能使用验证集并预先冻结规则，不能根据测试集搜索。

未在本次实现改进模型或评估工具，未启动服务器新任务，也没有将上述待验证推断标记为实验结论。
