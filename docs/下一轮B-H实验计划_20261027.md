1. 本轮目标与范围
只训练一个新候选 B-H（建议程序标识 B_Hstats），检验：在相同 λ＝0.05 分支监督下，将门控输入中的两路熵统计与前两类概率间隔，从原始表示 z 的统计替换为共享分类头 H(z) 的预测统计，能否改善最终融合，并超过全局权重 C。

本轮直接检验“统计输入来源的修改”，不是重新检验所有辅助监督方法，也不预先宣称能够保留融合挽救能力。H(z) 的输出有类别含义，但其概率不自动具备良好校准。

本轮预算按实验次数限定：已有缓存的一次小统计、实现与小规模探测、一次 seed42 完整训练、一次最佳检查点验证导出与分析。最多100轮并沿用早停；不设置额外墙钟或GPU小时截断。多 seed 和后续消融为条件触发任务。

3. 唯一候选的精确定义
3.1 已核对的当前结构
- 两个读取完整异构图的编码器，分别使用 Flow／Packet 池化视角；不是严格隔离的两种输入模态。
- 两路经 Linear(64,8) 得到 z_f、z_p；尽管代码变量叫 flow_logits、packet_logits，它们在这里是8维表示。
- H 为共享 Linear(8,32) → LeakyReLU → Linear(32,8)。
- 门控为 Linear(21,16) → LeakyReLU → Linear(16,2) → softmax。
- 最终预测仍为 H(w_f*z_f + w_p*z_p)，w_f＋w_p＝1；沿用无最终代理混合的前向。
3.2 只替换21维输入中的4维
定义 p_f＝softmax(H(z_f))，p_p＝softmax(H(z_p))。

沿用原函数计算：
- 熵补量 c(p)＝1＋Σ[p_k log(max(p_k,1e-8))]／log(8)。
- 前两类概率间隔 m(p)＝最大的预测概率－第二大的预测概率。
门控输入部分	旧 B	新 B-H
前16维	z_f 与 z_p	原样保留 z_f 与 z_p
第17～18维	softmax(z_f)、softmax(z_p) 的熵补量	p_f、p_p 的熵补量
第19～20维	softmax(z_f)、softmax(z_p) 的前两类概率间隔	p_f、p_p 的前两类概率间隔
第21维	cosine(z_f,z_p)	原样保留 cosine(z_f,z_p)


输入顺序以旧 B 的拼接顺序为准，网络维度及参数数量不变。不另加最大概率、JS散度、类别专用特征，也不把两段 z 换成概率向量。

门控输入中的“间隔”不使用真实标签；它与诊断中的“真实类别概率减去最高错误类别概率”不同。真实标签只用于训练损失和离线评价。
3.3 梯度与训练语义
读取的旧 B 统计路径没有 detach。B-H 也不新增 detach，保持端到端训练；门控、两路编码器、投影和共享 H 都参与训练，不冻结其参数。

H(z) 作为统计来源后，门控会新增经过 H 的梯度路径。这是本候选修改的一部分。若有收益，应表述为“以 H(z) 为来源的门控统计及相应训练路径有效”，不能单凭本轮把收益全部归因于概率语义。是否停止该路径梯度留作有希望之后的机制消融，本轮不增加候选。

推理时仍需计算两路 H(z) 以产生门控统计，因此相同参数量不代表相同推理计算量。可复用这两路结果计算训练辅助损失；记录缓存和重复计算方式。

5. 执行步骤及交付
第一步：一次缓存分组统计，随后冻结方案
只复用已有逐样本预测，查看旧 Z 挽救但 B 丢失的64个 WebBased 样本：B 中两路都正确、仅 Flow 正确、仅 Packet 正确、两路都错误，各有多少。

这用于解释已有错误，不用于制定类别规则、选取训练样本或选择逐样本权重。至少一路正确说明存在正确端点；两路都错误也不能证明混合路径没有正确区域。无需追加权重网格。如果缓存字段缺失，记录缺项，不重跑整轮历史诊断；该项不阻塞 B-H 的实现与训练。

在已有 B 实现上增加明确的输入来源开关或独立候选类，沿用现有构造、损失、采样和评价逻辑。旧 A／C／B 已登记的设计ID、源快照和输出目录保持历史身份，为本轮新建协议和候选标识。

第三步：一次小规模运行检查
使用训练集做3个batch的更新探测；正式训练另起干净初态，不能从探测后的参数继续。

验收内容：
1. 与 B 的初态参数一致；输入保持21维，四个替换统计值确实来自 H(z)，余下17维来源不变。
2. 初始实际权重全部为0.5／0.5，B 与 B-H 的初始融合输出和损失一致。
3. 输出与损失有限；辅助损失监督 H(z) 并传到共享头、投影和编码器；无标签进入门控输入。
4. 门控最后一层获得梯度并更新；允许零初始化造成第一步门控上游梯度为零，检查后续两步上游梯度和实际更新。
5. 记录新增 H→统计→门控的反向路径；没有新增类别损失或最终代理混合。
6. 若切回旧统计来源，应恢复旧 B 的前向及损失。检查失败先修复，不把有问题的运行计作实验结果。
第四步：只运行 B-H seed42 正式训练
复用冻结训练／验证划分和旧 B 的训练顺序。每轮记录损失、验证指标、权重分布、累计更新次数与实际曝光量。保持既定早停，不因 WebBased 子群表现改换检查点，也不为追齐旧模型停止轮次而延长训练。

保存 config、初态证据、逐轮日志、best／last checkpoint、metrics、完整验证预测缓存与实际训练源版本。共享GPU耗时仅作描述，不据此宣称速度优势。
第五步：最佳检查点的一次验证与配对分析
输出以下最小结果集：
- 全验证 Accuracy、Macro-F1、Weighted-F1，以及8类 P／R／F1和混淆矩阵。
- B-H 相对 B、C、E2、E0 的 Macro-F1 差值（单位：百分点）。
- B→B-H、C→B-H 的全体验证与逐类修复／退步；Z→B-H 可直接复用已保存的 Z 验证缓存。
- WebBased→Recon 和 Recon→WebBased 的双向混淆，不能只挑改善方向。
- 旧 Z 挽救的294个样本、其中104个 WebBased样本，在 B-H 中最终仍正确多少；以 B 的220／40为参照。

单路分数上升、平均权重变化或某个子集恢复均不能单独判为成功。核心依据仍是完整验证 Macro-F1。

7. 仅在通过筛选后执行的确认阶段
同一批 seed43、44 运行 B-H、B、C、E2；若 E0 相同协议的重复结果尚未具备，最终结构比较前一并补齐。最多10次追加训练，已有合规结果可复用。此阶段不改变 B-H 特征、λ、学习率、早停或选模规则。

每个seed报告 B-H−B（输入修改）、B-H−C（动态适应）、B-H−E2／E0（强基线比较），并给出配对差值均值和样本标准差。seed42明确标为探索筛选，43／44为冻结后确认；三个seed仍只构成初步稳定性证据。

只有冻结方案后的重复结果仍有收益，才安排必要的辅助监督去除消融。旧 Z 的门控统计来源不同，不能直接代替 B-H 的 λ＝0 版本。正式测试在全部方案选择与比较配置固定后统一进行，并披露早期已知的测试结果。

若下一候选也失败，暂停当前门控统计路线，保留 E0／E2，依据完整失败证据重新决定表示或融合结构研究；不连续增加损失或门控输入寻找单次高分。
